> 适用环境：Windows 10/11，不需要任何账号，完全离线
> 最后更新：2026-10-20（分支 `sensevoice`）

## 1. 这是什么

在任何软件里，**单按一下右 Alt** 开始说话，**再按一下**结束。文字自动输入到光标处，同时留在剪贴板里，并保存到历史记录。

- 语音识别用的是阿里开源的 **SenseVoice** 模型，在你自己电脑上运行：不联网、不要账号、没有次数限制，录音不会离开电脑。
- 运行模型用的是 **sherpa-onnx**（新一代 Kaldi 团队的轻量推理库），只用 CPU，不需要显卡，也不需要 PyTorch。
- 项目最早基于 Codex（ChatGPT 桌面应用）自带的听写，2026-10-20 因 GPT 转写受限，换成了本地 SenseVoice。Codex 版的代码保留在 `master` 分支，经过见[开发日志.md](开发日志.md)。

| 操作 | 效果 |
|---|---|
| 单按右 Alt | 开始录音："低→高"提示音 + 屏幕下方出现指示条：红点 + **随音量跳动的波形**（说话时条高，安静时变成一排小点）+ 计时 0:03 |
| 再单按右 Alt | 结束：指示条变成蓝点 +"识别中…"，约 0.2 秒后文字输入到光标处，"高→低"提示音 |
| 忘了结束 | 录满 5 分钟（`MAX_RECORD_SECONDS`）自动结束并识别 |
| Esc（录音中） | 取消本次录音，不输入任何东西；Esc 不会传给当前窗口 |
| 右 Alt + 其他键 | 正常组合键，不触发听写 |

## 2. 整体流程

```
你单按右 Alt
   │
   ▼
[sensevoice_hotkey.py] 键盘钩子判断"是单按"   ──(右 Alt + 别的键：不管，照常放行)
   │
   ▼
[sensevoice_hotkey.py] Toggle.press()
   ├─ 空闲 → [sensevoice_engine.py] Recorder.start()：打开麦克风（16 kHz 单声道）
   │         [sensevoice_overlay.py] 显示"● 波形 0:03" + 播放 start.wav
   │         （麦克风每来一小块声音就算一次音量 → 指示条每 0.05 秒取一次 → 画成波形）
   │
   └─ 录音中 → Recorder.stop()：关闭麦克风，拿到整段音频
             指示条变成"识别中…"
                │  （另开线程，不卡键盘）
                ▼
       [sensevoice_engine.py] Engine.transcribe()：本地 SenseVoice 转写
                │  （10 秒语音约 0.2 秒）
                ▼
       [sensevoice_utils.py] save_history() → history/history.jsonl
                             write_clipboard_text() → 剪贴板
       [sensevoice_hotkey.py] paste()：模拟 Ctrl+V，文字进入光标处
       指示条隐藏 + 播放 end.wav + 写日志 history/sensevoice.log（只记字数）
```

**关键点：整条链路都在本机完成**。麦克风只在"开始"和"结束"之间打开；音频只在内存里，转写完就丢掉，不写硬盘。

**波形的三个参数怎么理解**（`config.py`）

分贝（dBFS）：0 是麦克风能录到的最大声，越往负越小声，每 -6 dB 声音幅度减半。2026-10-20 实测你的 USB 麦克风在房间安静时是 **约 -42 dB**（这就是"底噪"）。

| 参数 | 值 | 含义 |
|---|---|---|
| `WAVE_SILENCE_DB` | `-38` | 低于它就显示成小圆点。设在底噪上方几 dB，**底噪和轻微杂音就不会让条动起来**。想更不敏感就调高（比如 -34） |
| `WAVE_LOUD_DB` | `-10` | 达到它就满格。离麦克风很近、大声说话时差不多到这里。调高 = 更难满格 |
| `WAVE_CURVE` | `1.6` | 弯曲程度。1 = 直线；大于 1 时小声被压得更小、大声基本不变，**对比度更强** |

两个 dB 之间相差 28 dB，按上面的设置，高度大约是：

| 声音 | 分贝 | 条的高度 |
|---|---|---|
| 房间底噪 | -42 | 0（小圆点） |
| 很远处小声说话 | -30 | 13% |
| 正常距离说话 | -25～-20 | 29%～49% |
| 靠近说话 | -15 | 73% |
| 贴着麦克风 / 大声 | -10 | 100% |

所以可以靠条的高度判断自己离麦克风的远近。之前的设置是 -55～-20 dB、直线映射：底噪本身就有 37% 高，正常说话就接近满格，所以看起来"一点响声就很大、对比度不够"。

### 4.6 键盘钩子的最小写法（学习用）

```python
@HOOKPROC
def hook(n_code, w_param, l_param):          # 系统每有一个按键事件就调用一次
    if n_code == 0:
        kb = ctypes.cast(l_param, ctypes.POINTER(KBDLLHOOKSTRUCT)).contents
        if detector.handle(w_param, kb):     # kb.vkCode = 哪个键；w_param = 按下/松开
            return 1                         # 拦下：窗口收不到
    return user32.CallNextHookEx(None, n_code, w_param, l_param)   # 放行

user32.SetWindowsHookExW(WH_KEYBOARD_LL, hook, kernel32.GetModuleHandleW(None), 0)  # 全局低层钩子
while user32.GetMessageW(ctypes.byref(msg), None, 0, 0) > 0: ...   # 消息循环，没有它回调不会被调用
```

写钩子的规矩：
- 回调里**只做判断，必须马上返回**。处理太慢的钩子会被 Windows 自动移除，所以录音、识别都放在别的线程。
- **程序自己模拟的按键也会经过钩子**，要打标记并跳过。
- 回调里的异常必须捕获，不能让键盘出问题。

## 5. 关键技术细节（改代码前必看）

### 5.1 单按 Alt 不激活菜单栏（"空按键"技巧）
- **Windows 的规则**：窗口收到"Alt 按下 → Alt 松开"，中间没有别的键，就会激活菜单栏。
- **程序的做法**：右 Alt **第一次按下**时把它拦下，然后自己**一次性按顺序**发出"右 Alt 按下 + 空键 0xE8 按下 + 空键松开"；**真正的松开原样放行**。窗口看到的是"Alt → 空键 → Alt 松开"，就认为是组合键。
- **为什么不只在后面补一个空键**：在钩子里模拟的按键，可能被系统排在当前这个 Alt 按下之前，顺序一乱就会失效（实测出现过）。
- **为什么不拦"松开"**：其他程序如果看不到真实的松开，会以为 Alt 一直按着（Codex 版时期出过这个问题）。

### 5.2 指示条不能抢焦点
文字是粘贴到"当前前台窗口"的。如果指示条抢走了焦点，文字就会贴到指示条上，等于丢了。所以指示条：
- 加了 `WS_EX_NOACTIVATE`，移动窗口时用 `SWP_NOACTIVATE`；
- 隐藏时**只把透明度设为 0**，不移动窗口。早期版本把它移到 -32000 来隐藏，而 -32000 正好是 Windows 存放最小化窗口的位置，Tk 因此把窗口当成"最小化"，之后再也移不回来了；
- Tk 设置的窗口位置对这个窗口不起作用，所以移动改用 Win32 的 `SetWindowPos`。

### 5.3 粘贴与剪贴板
- 识别完先把文字写进剪贴板，再模拟 Ctrl+V。粘贴完**不恢复原来的剪贴板**，听写文字会一直留在剪贴板里，方便再贴一次。
- 粘贴前会等所有修饰键（Shift/Ctrl/Alt/Win）松开，避免 Ctrl+V 变成别的组合键。
- 文字会贴到**结束那一刻的前台窗口**。

### 5.4 只有一个实例
- 程序用互斥锁 `Local\sensevoice_hotkey` 防止重复运行，重复双击启动不会开出两份。
- `stop_sensevoice.cmd` 会同时关掉旧名字 `codex_voice.py` 的进程。改名那天就出过新旧两版同时运行的问题，见开发日志第 12 轮。

### 5.5 历史和日志的写法（`append_capped`）
追加到末尾 → 超过上限时，把最新的 N 行写进临时文件 → 用 `os.replace` 一次性替换原文件（原子操作，不会写坏）。追加前会检查文件末尾有没有换行，即使你用编辑器改过文件也不会粘行。

### 5.6 识别效果和局限
- **中文、英文、日文、韩文、粤语**都能识别，也能识别中英混说，会自动加标点、把数字写成阿拉伯数字。
- 中英混说里的英文专有名词偶尔会错。实测用电脑合成语音时，把 "Codex" 识别成了 "codeex"；真人发音通常好一些。
- 是"说完再整段识别"，不是边说边出字。单次说太长（几分钟）也能识别，但建议一段话一按，效果更稳。
- 麦克风用的是 **Windows 默认录音设备**。换麦克风就在 Windows 声音设置里改默认设备；程序每次录完都会重新读设备列表，所以**不用重启**，下一次录音就用新设备。
- 英文：整句英文一般没问题；**中文里夹的英文单词、专有名词、缩写**是弱项（比如 Codex → codeex）。原因见 9.5，可选模型见 [模型调研.md](模型调研.md)。

### 5.7 已知限制
- **管理员权限运行的窗口**（如管理员命令行）里按右 Alt 不会触发，这是 Windows 的安全机制。
- 指示条显示在**按下右 Alt 那一刻鼠标所在的屏幕**上。

### 5.8 常驻内存、睡眠和稳定性
程序启动后模型就**一直在内存里**（约 360 MB），所以每次按键都立刻可用，不用重新加载。

| 情况 | 会发生什么 | 程序怎么处理 |
|---|---|---|
| 睡眠（S3 / 现代待机） | 内存一直通电，模型原样留着，醒来就能用 | 不需要处理 |
| 休眠（S4） | Windows 把内存写到硬盘，开机再读回来，模型也跟着回来 | 不需要处理 |
| 醒来后第一次按键 | 很久没用的内存可能被换到了硬盘，读回来时钩子回调会变慢。**Windows 的规矩：低层键盘钩子回调超时一次，就会被悄悄删掉**，之后按右 Alt 就再也没反应，日志里也看不出来 **不做自动处理**（和以前一样）。到目前为止没遇到过；万一遇到，双击 stop 再双击 start 重启程序即可 |
| 醒来后 USB 麦克风重新连接 / 换了麦克风 | 录音库启动时读的设备列表过时了，可能打不开麦克风 | 打不开就重读设备列表再试一次；每次录完也会在后台重读一次 |
| 录音时电脑睡着了 | 录音中断 | 醒来后按一下右 Alt 结束即可，已录到的部分照常识别；不管的话 5 分钟后自动结束 |
| 内存紧张 | Windows 可能把模型的一部分换到硬盘 | 下次识别会慢几十到几百毫秒，之后恢复正常，不会出错 |

**关于"定时重装钩子"：** 第 17 轮曾加过"每 60 秒重装一次钩子"的保险，第 20 轮按你的意见去掉了，恢复成和以前一样只装一次。理由：以前从没出过问题，没必要为没遇到的情况每分钟做一次额外操作。

**已经确认没问题的点：**
- **识别时不会卡键盘**：sherpa-onnx 识别时会释放 Python 的全局锁（GIL）。实测识别 20 秒音频（用时 0.58 秒）期间，另一个线程最长只被卡了 14 毫秒，键盘钩子不受影响。
- **第一次识别不需要"预热"**：实测加载后第一次识别 3 秒音频用 93 毫秒，之后是 80～88 毫秒，差别可以忽略，所以没有加预热代码。

## 9. 模型原理：SenseVoice 和 sherpa-onnx

### 9.1 SenseVoice 是什么
- 阿里通义实验室（FunAudioLLM 团队）2024 年 7 月开源的语音识别模型。我们用的是 **SenseVoice-Small**，约 2.3 亿参数，用 40 多万小时的数据训练，支持中、英、日、韩、粤语。
- **一个模型直接输出带标点的文字**，不需要另外再接一个"加标点模型"。
- 除了文字，它还能输出语种、情绪（开心、生气……）、声音事件（笑声、掌声、音乐……）。这些标签 sherpa-onnx 会从文字里去掉，程序只用文字。

### 9.2 为什么自带标点
SenseVoice 在输入的音频前面加了 4 个"任务提示"：**语种**、**情绪**、**事件**、**是否做文本规范化（ITN）**。训练时用了两种标注：一种带标点、数字写成阿拉伯数字，一种不带。所以推理时只要选"做 ITN"（代码里的 `use_itn=True`），模型就会**直接**输出带标点、数字规范的文字。把 `use_itn` 改成 `False`，就会得到不带标点的纯文字。

**和 Whisper 对比**：Whisper 本身也会输出标点，英文通常没问题；但**中文**训练数据里很多文本没有标点，所以 Whisper 识别中文经常没有标点，有时还会输出繁体字。你之前遇到的"只出字、没标点"，就是这个原因。

### 9.3 为什么这么快
| | Whisper（自回归） | SenseVoice（非自回归） |
|---|---|---|
| 结构 | 编码器 + 解码器 | **只有编码器** + CTC 输出层 |
| 出字方式 | 解码器**一个字一个字**往外生成，每出一个字都要再跑一遍解码器，100 个字就要跑 100 遍 | 编码器跑**一遍**，每一小段时间直接给出"这里是哪个字（或空白）"，所有位置**同时**算出来，再合并重复、去掉空白 |
| 输入长度 | 原版不管音频多短，都补齐成 30 秒再算 | 多长算多长 |
| 速度（论文数据） | — | 10 秒音频 70 毫秒，比 Whisper-Large 快 15 倍 |

再加上两点：
- **低帧率**：先把音频切成 10 毫秒一帧的特征，再每 6 帧合并成一帧（每帧 60 毫秒），10 秒音频只剩约 170 帧要算；
- **int8 量化**：权重从 32 位浮点压成 8 位整数，模型从约 900 MB 变成 229 MB，CPU 计算也更快，准确率几乎不变。

所以在本机 CPU 上，10 秒语音只要约 0.2 秒。

**代价**：CTC 每个位置是"各自独立"判断的，不像 Whisper 的解码器那样会参考前面已经写出的字。所以 SenseVoice 对**上下文语义**的利用弱一些，在中文里夹的英文词、专有名词上更容易出错（9.5）。

### 9.4 sherpa-onnx 为什么能代替 PyTorch
- **PyTorch 是"训练 + 推理"的全能框架**：自动求导、优化器、GPU 训练、动态计算图，这些都只有训练时才用得上。装一个 CPU 版就要几百 MB，GPU 版要 2～3 GB。官方的 FunASR 方式运行 SenseVoice，需要 PyTorch + torchaudio + funasr + modelscope 这一整套。
- **推理只需要"前向计算"**：说到底就是一串矩阵乘法、卷积、softmax 之类的固定运算。
- **ONNX** 是一种通用的模型格式：用 PyTorch 把模型的计算图和权重**导出**成一个 `.onnx` 文件（我们的 `model.int8.onnx`）。算的是同一套公式、用的是同一份权重，所以结果和 PyTorch 跑出来的一样（int8 版有极小差异）。
- **onnxruntime**（微软出的推理引擎）专门执行 `.onnx` 文件：只做推理，有针对 CPU 指令集（AVX2 等）优化过的计算核心，还会把相邻的运算合并、提前算好常量。在本项目里它就是一个 **17.8 MB 的 `onnxruntime.dll`**。
- **sherpa-onnx**（小米"新一代 Kaldi"团队，k2-fsa）在 onnxruntime 外面补齐了语音识别需要的其他部分：读音频、算声学特征（fbank）、CTC 解码、把编号转成文字（`tokens.txt`），用 C++ 写，提供 Python 接口。整个包 28 MB。

| | PyTorch + FunASR 方式 | sherpa-onnx 方式（本项目） |
|---|---|---|
| 安装体积 | 约 1～3 GB | **整个 `.venv` 117 MB**（sherpa-onnx 28 MB、numpy 55 MB、sounddevice 2 MB） |
| 启动 | 加载框架要好几秒 | 约 1.2 秒 |
| 内存 | 通常 1 GB 以上 | 约 360 MB |
| 能不能训练 | 能 | 不能（我们也不需要） |

### 9.5 英文识别不准：原因和可选方案（**换模型前会先和你确认**）
**原因**：
1. 训练数据以中文为主，英文少一些；
2. 中英混说时，`auto` 语种判断按整句来，判成中文后，英文词更容易被"听成"拼音近似的写法；
3. CTC 不参考上下文（9.3），专有名词（Codex、GitHub……）没有"联想"能力；
4. 这个模型**不支持热词**（不能告诉它"Codex 是个词"）。

**可选方案**（都还没做）：
- **不换模型**：用个人词库在识别后纠正（比如 `codeex → Codex`），可以自动学习。方案见 [词库与纠错方案.md](词库与纠错方案.md)，还没实现。
- **换模型**：中英混说的公开测试里，SenseVoice-Small 已经是 2024 年那一代模型里最好的；想明显更好，要换成 Fun-ASR-Nano 或 Qwen3-ASR 这类"大语言模型解码"的新模型，代价是更慢、更占内存。详细的 benchmark、链接和建议见 **[模型调研.md](模型调研.md)**。换模型前一定先和你确认。

### 9.6 Python 环境装在哪里：`.venv` 和 conda 的关系
| 位置 | 是什么 |
|---|---|
| `D:\conda\miniconda3\` | 你电脑上原来就有的 conda。它提供 **Python 解释器本身**（`python.exe` 3.12.9）和标准库 |
| `D:\interpret_codex\.venv\` | 本项目**自己的环境**（123 MB），由 `setup.py` 用上面那个 Python 运行 `python -m venv` 创建 |
| `D:\interpret_codex\.venv\pyvenv.cfg` | 记录"我借用的是哪个 Python"：`home = D:\conda\miniconda3` |
| `D:\interpret_codex\.venv\Lib\site-packages\` | 本项目装的第三方库都在这里：`sherpa_onnx`（28 MB，含 17.8 MB 的 `onnxruntime.dll`）、`numpy`（55 MB）、`sounddevice`（2 MB） |
| `D:\interpret_codex\.venv\Scripts\pythonw.exe` | 6 MB 的启动器。它读 `pyvenv.cfg`，拉起 conda 的 `pythonw.exe`，并让它**只看 `.venv` 里的库** |

**关系**：`.venv` 借用 conda 的 Python 解释器，但**库是自己的一套**（`include-system-site-packages = false`），和 conda 里装的东西互不影响。所以任务管理器里真正干活的进程显示的路径是 `D:\conda\miniconda3\pythonw.exe`。

**为什么放在项目文件夹里**：
- 不会污染 conda 的 base 环境，也不会被你以后在 conda 里升级、卸载的包影响；
- 依赖版本固定在 `requirements.txt`，哪台电脑装出来都一样；
- 不想要了，删掉项目文件夹就干净了；
- 缺点：`.venv` 记死了 conda 的路径，**不能复制到别的电脑**，所以迁移时让 `setup.py` 重新建。

**注意**：如果以后卸载或移动了 conda（`D:\conda\miniconda3`），`.venv` 会失效，重新运行一次 `python setup.py` 即可。

### 10.2 关键代码长什么样

**加载模型 + 识别**（`sensevoice_engine.py`），整个识别就这几行：
```python
recognizer = sherpa_onnx.OfflineRecognizer.from_sense_voice(
    model="…/model.int8.onnx", tokens="…/tokens.txt",
    num_threads=4, language="auto", use_itn=True)   # use_itn=True：带标点

stream = recognizer.create_stream()
stream.accept_waveform(16000, audio)   # audio：float32 数组，16 kHz 单声道
recognizer.decode_stream(stream)       # 跑一遍模型（会释放 GIL）
text = stream.result.text
```

**录音 + 音量**（`sensevoice_engine.py`）：
```python
def _on_audio(self, indata, frames, time_info, status):     # 每约 10 毫秒调用一次
    block = indata[:, 0].copy()
    self._chunks.append(block)                               # 存起来，结束时拼成整段
    self._energy += float(np.dot(block, block))              # 累加能量
    self._count += len(block)

def take_level(self):                                        # 指示条每 0.05 秒来取一次
    energy, count = self._energy, self._count
    self._energy, self._count = 0.0, 0
    return (energy / count) ** 0.5 if count else 0.0         # 这 50 毫秒的平均音量 RMS
```

## 11. 版本管理与上传 GitHub

### 11.1 本地有哪些分支和标签
| 名字 | 是什么 |
|---|---|
| `master` | Codex 版，**只在本地，不上传** |
| `sensevoice` | 日常开发的分支，完整历史（前 10 个提交是 Codex 时期的） |
| `publish` | **专门用来上传的分支**：内容和 `sensevoice` 一模一样，但没有 Codex 时期的历史 |
| `v2.0-sensevoice`、`v2.1-waveform` | 本地标签，打在 `sensevoice` 上，不上传 |
| `v2.1` | 打在 `publish` 上的标签，上传用 |
| 远程 `origin` | `git@github.com:th0nly/dictation_local.git` |

### 11.2 "只传 SenseVoice 部分"是怎么做到的
git 的每个提交 = "一份文件快照" + "上一个提交是谁"。正常提交都连着上一个，所以历史是一条链。

```bash
git commit-tree "sensevoice^{tree}" -m "说明"
```
- `sensevoice^{tree}` 取的是 sensevoice 当前的**文件快照**；
- 不写 `-p`（parent），新提交就**没有上一个**，是一条新链的起点；
- 结果：文件完全相同，但历史里只有这一个提交，看不到 Codex 时期的任何东西。

然后 `git branch -f publish <这个提交>` 让 `publish` 指向它，`git tag -a v2.1 <这个提交>` 打标签。

### 11.3 "master 不传、只传一个标签"是怎么做到的
`git push` **只推送你点名的东西**：
```bash
git push origin publish:sensevoice v2.1
```
- `publish:sensevoice`：把本地的 `publish` 推到 GitHub 上，名字叫 `sensevoice`；
- `v2.1`：只推这一个标签；
- 没点名的 `master`、本地的 `sensevoice`、另外两个标签都不会被推送。只有写 `--all` 或 `--tags` 才会全推，**不要用这两个参数**。

### 11.4 第一次上传（你自己执行）
1. 把公钥登记到 GitHub：先复制公钥 `cat ~/.ssh/id_rsa_project1.pub | clip`，再到 GitHub → Settings → SSH and GPG keys → New SSH key 粘贴保存；
2. 测试：`ssh -T git@github.com`，看到 `Hi th0nly!` 就是成功；
3. 在项目文件夹里推送：`git push origin publish:sensevoice v2.1`。

### 11.5 以后发新版本（比如 v2.2）
在 `sensevoice` 上正常开发、提交，然后：
```bash
git checkout sensevoice
git branch -f publish $(git commit-tree "sensevoice^{tree}" -p publish -m "v2.2: 改了什么")
git tag -a v2.2 -m "v2.2" publish
git push origin publish:sensevoice v2.2
```
这次加了 `-p publish`：新提交接在上一次上传的提交后面，GitHub 上的历史就是 v2.1 → v2.2 一条干净的链，**不需要强制推送**。
