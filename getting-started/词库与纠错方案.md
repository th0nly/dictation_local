# 词库与纠错方案（只是方案，还没有实现）

> 2026-10-20 整理。目标：中文里夹的英文单词、专有名词（Codex、GitHub、人名、项目名……）识别错了，改过一次以后，以后能自动认对。
> 相关文档：[模型调研.md](模型调研.md)、[项目说明.md](项目说明.md) 9.5

---

## 1. 先说清楚难点

程序把文字粘贴出去以后，就**不知道你后来把它改成了什么**。所以任何"自动学习"都要解决两个问题：

1. **怎么知道你改了什么**（学习的来源）；
2. **学到以后怎么用上**（纠正的方式）。

下面分开讲。

---

## 2. 我们提过的三个方案（记录）

| 方案 | 怎么用 | 优点 | 缺点 |
|---|---|---|---|
| **① 手写表** | `replacements.txt` 一行一条，比如 `codeex => Codex`，改完不用重启 | 简单、可靠 | 要自己写 |
| **② 一键纠错** | 粘贴后在原处把错词改对，再按一个纠错键。程序读出输入框里现在的文字，和刚才粘贴的对比，把改动加进表 | 只在你按键时才读，不会误学 | 要多按一下；有些软件的输入框读不到（终端、部分编辑器） |
| **③ 全自动** | 每次粘贴后，等你下一次听写时，程序自动读一次上一个输入框，对比出你改了什么；同一处改动出现 2～3 次才自动加进表 | 完全不用管 | 会读取你输入框里的内容；内容上的修改可能被误当成识别错误，需要过滤规则；读不到的软件学不了 |

这三个都属于"**识别完以后按规则替换文字**"，是最底层、最简单的一类。

---

## 3. 更成熟的做法

业界的做法大致分 4 层，越往下越成熟、效果越好，代价也越大：

| 层次 | 做法 | 谁在用 | 本项目能不能用 |
|---|---|---|---|
| **A. 规则替换** | 错法 → 正确写法，一对一替换（就是上面的 ①②③） | Wispr Flow 的"Correct a Misspelling"选项，就是让你填"常被听错成什么" | ✅ 现在就能用 |
| **B. 词库 + 模糊匹配** | 只存**正确的词**（Codex、GitHub），不存错法。识别完把结果里"拼写或读音很像词库里某个词"的片段换成那个词。比如 `codeex` 和 `Codex` 只差一个字母，就换掉 | 很多输入法的"个人词库"思路 | ✅ 现在就能用；比 A 省事：一个词只要存一次，各种错法都能纠正 |
| **C. 热词（让模型在识别时就偏向词库里的词）** | 把词库交给模型，模型识别时会优先往这些词上靠，而不是事后再改 | 阿里 Fun-ASR、Qwen3-ASR 的官方功能；FunASR 的 SeACo-Paraformer；sherpa-onnx 的 transducer 模型 | ⚠ **现在的 SenseVoice 不支持**。但你装的 sherpa-onnx 1.13.8 里，`from_funasr_nano(…, hotwords=…)` 和 `from_qwen3_asr(…, hotwords=…)` **都有 `hotwords` 参数**（已在本机确认）。换模型后就能用 |
| **D. 大语言模型润色** | 识别完把文字和词库一起交给大语言模型，让它改错、加标点、去掉"嗯啊" | Typeless、Wispr Flow（都是云端） | ❌ 本地跑要再加一个大模型，内存和速度代价大；用云端又违背"全部本地、免费" |

**结论**：最成熟的组合是"**一个个人词库 + 自动学习往词库里加词 + 识别时用热词**"。现在的 SenseVoice 不支持热词，所以先用 B（模糊匹配）代替 C，以后换模型时直接把同一个词库当热词传进去。

## 4. Typeless 是怎么做的、能借鉴什么

公开资料能确认的：

- Typeless 有**个人词库**（Personal Dictionary），可以手动加人名、术语、缩写，也能搜索、修改、删除。
- macOS 版发布说明里写：**听写后你马上改掉某个词，它会把改正后的词自动存进个人词库**。举的例子是同事名字、项目代号、品牌名。
- 它是云端服务（没有离线模式），识别后还会用大语言模型润色。

公开资料**没有**说明的：它具体怎么发现你改了词、要改几次才收录、怎么用这个词库（猜测是作为上下文交给云端模型，但官方没写）。

**它大概是怎么做到的（推断，官方没写）：**

macOS 有一套"辅助功能接口"（Accessibility API），本来是给读屏软件用的：任何程序在用户授权后，都能**读到当前输入框里的文字**，还能**订阅"这个输入框的内容变了"的通知**。Typeless 安装时会要求你在"系统设置 → 隐私 → 辅助功能"里授权，就是为了这个（它也靠这个把文字插进输入框）。所以合理的流程是：

1. 把文字插进输入框，记下"插入了什么、插在哪个输入框"；
2. 接下来一小段时间里，订阅这个输入框的"内容变化"通知；
3. 你改了字，它就读出新内容，和刚才插入的原文逐字对比，找出"哪个词被换成了哪个词"；
4. 判断这是在纠正识别错误（改动很小、发生在刚插入的那段文字里、改后像一个名字或术语），就把**改后的词**存进词库；
5. 下次识别时，把词库作为上下文交给云端模型。

Windows 上有对应的东西：**UI Automation**（同样是给读屏软件用的系统接口，Windows 自带，不用授权弹窗），能读输入框文字、订阅文字变化。所以同样的流程在 Windows 上也能做。

**可以借鉴的三点**：

1. **只在"听写后马上改"的时候学习**。听写结束后短时间内（比如 30 秒）你在同一个输入框里做的改动，最可能是在纠正识别错误；过了很久的修改多半是在改内容，不学。这能解决方案 ③"误学"的问题。
2. **存的是"正确的词"，不是"错法"**。词库里只有 Codex，不管它被听成 codeex 还是 code x，都能纠正（对应第 3 节的 B）。
3. **词库可以查看、删除**。学错了能删掉。

## 5. 推荐方案（等你决定）

**一个词库文件 + 三种加词方式 + 两种用法**：

```
             加词                              用词
  手动写进 dictionary.txt ─┐
  听写后 30 秒内的改动自动学 ─┼─→ dictionary.txt ─┬─→ 现在：识别完做模糊匹配纠正（方案 B）
  （可选）一键纠错键 ────────┘   （可看、可删）   └─→ 以后换模型：直接当热词传给模型（方案 C）
```

**需要增加什么——不需要任何模型：**

| 需要的东西 | 是什么 | 大小 |
|---|---|---|
| 读输入框文字 | Windows 自带的 UI Automation，用 `comtypes`（纯 Python 库）调用 | 约 1 MB |
| 找出改了哪个词 | Python 自带的 `difflib` 逐字对比 | 0（标准库） |
| 判断像不像 | 编辑距离、是不是英文/大写开头之类的简单规则 | 0（自己写几十行） |
| 模糊匹配纠正 | 同上，字符串比较 | 0 |
| 词库 | 一个 `dictionary.txt` 文本文件 | 几 KB |

**模型还是只有现在这一个 SenseVoice**，内存基本不变；只在听写后的 30 秒内多做几次读取和对比，CPU 可以忽略。

**自动学习的具体规则**（借鉴 Typeless）：
- 只在听写结束后 **30 秒内** 学习，而且只读**刚才粘贴的那个输入框**（用 Windows 的 UI Automation 读）；
- 只学**短的改动**（1～3 个词），而且改前改后**拼写相近**（比如编辑距离不超过一半），或者改后是英文/专有名词；
- 新词先进"候选"区，**同一个词出现 2 次才正式收录**；
- 每次学到新词，日志里记一行，`dictionary.txt` 里能看到、能删。

**代价和风险**：
- 程序会在听写后 30 秒内读一次你当前输入框的文字（只在本机处理，不保存原文，只保存学到的词）；
- 终端、部分编辑器、游戏等读不到输入框的软件学不了，但手动加词仍然有效；
- 模糊匹配可能误伤：比如词库里有 `Codex`，你本来就想说 `code`。所以要求足够相近才替换，并且可以给单个词关掉模糊匹配；
- 工作量：词库和模糊匹配约半天；自动学习（UI Automation + 对比 + 过滤）约一天，需要在你常用的软件里逐个测试。

**自动学习的隐患：改到一半就被学走**

比如 `codeex` 你想改成 `Codex`，删到 `cod`、打到 `Code` 的时候，程序如果正好去读，就会学到错误的词。缓解办法：
- **等你停手再读**：输入框内容 3 秒没再变化、或者焦点离开这个输入框时才对比；
- 只学"整个词被替换"的改动，删了没补上的、只改了一半的不学；
- 同一个词出现 2 次才收录（偶尔学错一次不会生效）。

这些能把误学降到很低，但**不能保证为零**。所以更稳的是下面的"纠错键"。

### 5.1 替代方案：纠错键（推荐先做这个）

**用哪个键：单按右 Ctrl。**

| 候选 | 评价 |
|---|---|
| **单按右 Ctrl**（推荐） | 平时几乎没人单独按它；右 Ctrl + 别的键照常可用；和右 Alt 挨着，好找；不会激活菜单栏（只有 Alt 会），比右 Alt 更简单；你不要英文模式，这个键正好空着。可以直接复用现在的"单按检测"代码 |
| 双击右 Alt | 会和"开始/结束听写"冲突（第一下就开始录音了） |
| 右 Shift | 打字时常按，容易误触 |
| F13～F24 | 键盘上一般没有 |
| 右 Alt + 某个键 | 中文输入法和部分软件会占用 Alt 组合键 |

注意：有些笔记本没有右 Ctrl，到时可以在 `config.py` 里换成别的键。

**用法（两种都支持）：**
1. **改完按一下**：听写出错，你在原处把 `codeex` 改成 `Codex`，然后单按右 Ctrl。程序读出输入框现在的文字，和刚才粘贴的原文对比，把 `Codex` 加进词库。提示音 + 指示条显示"已学习：Codex"。
2. **选中再按**（读不到输入框的软件，比如终端）：用鼠标选中正确的词 `Codex`，单按右 Ctrl。程序模拟 Ctrl+C 复制选中的词，加进词库。这个方式**任何软件都能用**。

**两种用法的区别**（程序自动判断：有选中文字就走第 2 种，没有就走第 1 种）：

| | ① 改完按一下 | ② 选中再按 |
|---|---|---|
| 要不要选中 | **不用** | 要选中正确的词 |
| 程序怎么知道学哪个词 | 用 UI Automation 读出整个输入框，和**最近一次**粘贴的原文对比，自动找出被改的词（一次改了几个就学几个） | 你选中的就是要学的词 |
| 能用在哪 | 只有能读出输入框文字的软件（记事本、Word、浏览器输入框、微信等大多数软件） | **任何软件**，包括终端 |
| 能学哪些词 | 只能纠正**最近一次**听写的错 | 任何时候、任何词，跟听写无关也行（比如提前教它同事名字） |
| 剪贴板 | 不碰 | 要模拟"复制"拿到选中的词，学完把原来的剪贴板内容放回去 |

实现时要注意：②的"复制"用 **Ctrl+Insert** 而不是 Ctrl+C，因为在终端里没选中文字时，Ctrl+C 会中断正在运行的程序。

**优点**：只在你按键时才学，不会改到一半被学走；也不会在你不知情时读输入框。
**缺点**：每个新词要多按一下（但一个词只需要教一次）。

**建议的顺序**：
1. 先做"词库文件 + 模糊匹配 + 右 Ctrl 纠错键"；
2. 用一段时间，如果觉得每次按键麻烦，再加"停手 3 秒后自动学习"；
3. 以后如果按 [模型调研.md](模型调研.md) 换成 Fun-ASR-Nano / Qwen3-ASR，词库直接当热词用，模糊匹配可以关掉。
