## 第 8 轮：应用快照换键 + 键盘钩子重写（约 16:45–16:55，git `d6b99a2` 16:58）⚠ 这一轮改动多、有反复

**你的要求：**
1. 声音哪来的，为什么单独存文件？
2. 应用快照别设成空，绑到别的键（设置里没找到在哪）。
3. 钩子一般怎么写？
4. 绑定的到底是什么键，为什么 Alt+空格没反应？

**过程（按时间顺序）：**
1. **找设置位置：** 应用快照的设置不在"键盘快捷键"页面，而在 **设置 → 应用快照 → 快捷键**。Windows 上只有三个选项：Alt + Alt（`DoubleAlt`）、Shift + Shift（`DoubleShift`）、无。
2. **发现更深层的原因：** "Alt + Alt"的意思是"两个 Alt **同时**按下"，你只按右 Alt，按理不会触发。推断原因是第 4 轮的写法**拦下了真正的右 Alt 松开**，再由程序模拟一个松开。Codex 的钩子大概率忽略模拟按键，于是一直以为右 Alt 还按着，你之后再按左 Alt，它就认为"两个 Alt 同时按下"。
3. **钩子改写，尝试 1（失败）：** "按下"和"松开"都不拦，只在右 Alt 按下时补发空按键。
   - 带菜单栏的测试窗口里，单按右 Alt 后打"34"，**只进去了"4"**，"3"被菜单栏吃了。
   - 原因：在钩子回调里模拟的按键，可能被系统排在当前这个"Alt 按下"之前处理，顺序乱了。
   - 所以放弃了这个方案。
4. **钩子改写，尝试 2（最终版）：** 拦下右 Alt 的**第一次按下**，自己一次性按顺序发出"右 Alt 按下 + 空键按下 + 空键松开"；**真正的松开原样放行**。
   - 菜单栏测试连续 3 次全部通过（打出"1234"）；
   - 右 Alt + F12 不触发听写，Alt 没有卡住；
   - 完整听写成功。
5. **应用快照绑定 `DoubleShift`**：关闭 Codex，修改设置，**重启 Codex**。日志显示 `Registering appshot hotkey hotkey=DoubleShift`，之后 0 次误触发。

**回答：**
- 声音是用代码合成的，不是从网上找的。存成文件是因为播放方便，也方便你替换。
- 钩子的三个部分：回调函数、`SetWindowsHookExW` 注册、消息循环。
- 绑定的是"单按右 Alt"。Alt+空格中间按了空格，算组合键，所以不触发听写，这是有意的设计。

## 反复和冲突汇总（看这一节就能知道哪些决定改过）

| 主题 | 第一次 | 后来 | 原因 |
|---|---|---|---|
| 触发键 | Ctrl+Alt+D（第 1 轮，`RegisterHotKey`） | 单按右 Alt（第 4 轮，键盘钩子） | 你要求像 Typeless 那样只按一个键 |
| Codex 内部快捷键 | Ctrl+Alt+D | F24 | Codex 要连按两下才开始，需要由程序代按；F24 不会和任何键冲突 |
| 处理菜单栏的方法 | v1：拦"松开"，补发空键和松开（第 4 轮） | v2：不拦，只在按下后补空键（**失败**）→ v3：拦"按下"，补发按下和空键，放行真正的松开（第 8 轮，最终版） | v1 让其他程序以为 Alt 卡住，导致应用快照误触发；v2 顺序不可靠 |
